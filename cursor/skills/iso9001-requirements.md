## 7.5 文書化した情報

### 7.5.1 一般

QMSは以下を含む必要がある：
- ISO規格が要求する文書化した情報
- QMSの有効性のために必要と組織が決定した文書化した情報

**土木設計への適用**:
品質マニュアル、設計手順書、検査要領、記録様式を文書体系として整備

### 7.5.2 作成及び更新

文書化した情報を作成・更新する際の要求：

| 要求項目 | 内容 | システム実装 |
|----------|------|--------------|
| a) 識別・記述 | タイトル、日付、作成者、参照番号 | メタデータ自動付与 |
| b) 形式 | 言語、ソフトウェア版、図表 | テンプレート、フォーマット標準化 |
| c) レビュー・承認 | 適切性・妥当性の確認 | 承認ワークフロー |

### 7.5.3 文書化した情報の管理

#### 7.5.3.1 管理要求

| 要求 | 説明 | システム実装 |
|------|------|--------------|
| a) 入手可能・利用適切 | 必要時に必要場所で使用可能 | クラウドアクセス、検索機能 |
| b) 適切な保護 | 機密喪失、不適切使用、完全性喪失の防止 | アクセス権限、暗号化 |

#### 7.5.3.2 管理活動

| 活動 | 説明 | システム実装 |
|------|------|--------------|
| a) 配付、アクセス、検索、利用 | 文書の流通管理 | 配付管理、アクセスログ |
| b) 保管・保存（読みやすさ保持含む） | 長期保存 | PDF/A形式、バックアップ |
| c) 変更管理（版管理等） | 改訂の追跡 | バージョン管理システム |
| d) 保持・廃棄 | ライフサイクル管理 | 保管期限、自動アーカイブ |

### 電子文書管理の具体的要件

```yaml
識別:
  - ファイル名規則の統一
  - メタデータ管理（タイトル、作成者、作成日、版数等）
  - 一意の文書番号体系

形式:
  - 長期保存形式（PDF/A推奨）
  - 互換性のある形式
  - 文字化け・レイアウト崩れ防止

入手可能性:
  - クラウドベースアクセス
  - 全文検索機能
  - オフライン対応（必要時）

保護:
  - アクセス権限管理（読取/編集/削除）
  - 暗号化（保存時・転送時）
  - 改ざん防止（電子署名、ハッシュ値）

版管理:
  - 自動バージョン採番
  - 改訂履歴の自動記録
  - 旧版の識別・保存

バックアップ:
  - 定期自動バックアップ
  - 地理的分散（災害対策）
  - 復元手順の確立

完全性:
  - 電子署名
  - タイムスタンプ
  - ハッシュ値検証
```

## 8.3 製品及びサービスの設計・開発

### 8.3.1 一般

設計・開発プロセスの確立、実施、維持を要求

### 8.3.2 設計・開発の計画

計画時に考慮すべき10項目：

| 項目 | ISO要求 | 土木設計への適用 |
|------|---------|------------------|
| a) 性質、期間、複雑さ | 設計活動の特性把握 | 橋梁/道路の区分、工期、難易度 |
| b) プロセス段階 | 必要なステージの決定 | 基本設計→詳細設計→照査のDRポイント |
| c) 検証・妥当性確認活動 | V&V活動の計画 | 構造計算チェック、現地検証 |
| d) 責任・権限 | 役割の明確化 | 主任技術者、照査技術者、管理技術者 |
| e) 内部・外部資源 | 必要資源の特定 | CADソフト、計算ソフト、外部コンサル |
| f) インターフェース管理 | 関係者間の連携 | 協力会社との情報連携、発注者との調整 |
| g) 顧客・ユーザー参画 | 利害関係者の関与 | 発注者レビュー、住民説明 |
| h) 以降の提供要件 | 後工程への引継ぎ | 施工者への設計意図伝達 |
| i) 管理レベル | 期待される管理の程度 | 品質等級に応じた照査レベル |
| j) 文書化 | 必要な記録の決定 | 設計計画書、照査記録 |

### 8.3.3 設計・開発へのインプット

#### 必須インプット項目

```yaml
機能・パフォーマンス要求:
  - 道路幅員、車線数
  - 設計速度
  - 耐荷重（設計荷重）
  - 耐久性要件（供用期間）
  - 環境条件（積雪、塩害等）

以前の類似活動からの情報:
  - 過去案件図面
  - 失敗事例・教訓
  - 成功事例・ベストプラクティス

法令・規制要求事項:
  - 道路構造令
  - 河川法、河川管理施設等構造令
  - 各種設計基準（道示、土工指針等）
  - 環境基準（騒音、振動、水質等）

組織の標準:
  - 社内設計標準
  - CADレイヤー規則
  - 図面表記基準

失敗の潜在的結果:
  - 構造的リスク
  - 安全リスク
  - 環境リスク
  - コストリスク
```

#### インプット要件

- 明確（Unambiguous）
- 完全（Complete）
- 相反なし（Without conflict）
- 文書化して保持

### 8.3.4 設計・開発の管理

#### レビュー（Review）

```yaml
目的: 設計結果が要求事項を達成可能かを評価
実施者: 設計に直接関与していない者を含む
時期: 計画した段階で実施
記録: 
  - 参加者
  - 審議内容
  - 判定結果
  - 指摘事項
  - フォローアップ
```

#### 検証（Verification）

```yaml
目的: アウトプットがインプット要求事項を満たすことを確認
問い: "正しく作ったか？"（Are we building the product right?）
活動例:
  - 設計計算書の照査
  - 図面チェック（寸法、整合性）
  - CADデータの検証
  - 数量計算の確認
記録:
  - 検証方法
  - 検証結果
  - 不適合事項と処置
```

#### 妥当性確認（Validation）

```yaml
目的: 製品・サービスが意図した用途の要求事項を満たすことを確認
問い: "正しいものを作ったか？"（Are we building the right product?）
活動例:
  - 現地検証
  - 試験施工
  - シミュレーション
  - ユーザー評価
時期: 可能な限り製品引渡し前
記録:
  - 妥当性確認方法
  - 確認結果
  - 条件付き承認の場合はその条件
```

### 8.3.5 設計・開発からのアウトプット

#### アウトプット要件

| 要件 | 説明 | 土木設計での例 |
|------|------|----------------|
| a) インプット要求事項を満たす | 設計条件への適合 | 設計計算で荷重条件クリア |
| b) 以降のプロセスに適切 | 施工可能性 | 施工手順、施工精度が実現可能 |
| c) 監視測定要求事項と合否判定基準 | 品質基準の明示 | 出来形管理基準、品質管理基準 |
| d) 安全・適切な使用に不可欠な特性 | 安全要件の明示 | 安全施設、注意事項 |

#### 土木設計アウトプット構成

```
成果物:
├── 設計図面
│   ├── 一般図
│   ├── 構造図
│   ├── 詳細図
│   └── 付属物図
├── 設計計算書
│   ├── 設計条件
│   ├── 構造計算
│   └── 安定計算
├── 数量計算書
├── 施工計画（設計段階）
│   ├── 施工手順の前提
│   └── 仮設計画
├── 品質管理基準
└── 検査要領
```

### 8.3.6 設計・開発の変更

変更時の要求：
- 変更の識別
- レビュー
- 要求事項への継続的適合の確実化
- 変更の悪影響がないことの確認

記録すべき情報：
- 変更内容
- レビュー結果
- 変更を許可した人
- 必要な処置

## 8.5.2 識別及びトレーサビリティ

### 要求事項

```yaml
識別:
  目的: 製品・サービスの適合を確実にする
  手段: アウトプットを識別する適切な方法
  適用: 製造・サービス提供の全過程

状態識別:
  目的: 監視測定要求事項に関連したアウトプット状態の識別
  例: 検査前/検査中/検査済/合格/不合格

トレーサビリティ:
  条件: トレーサビリティが要求事項である場合
  要求: アウトプットの一意の識別を管理
  記録: 文書化した情報として保持
```

### 土木設計での識別体系

```
プロジェクト識別:
  PRJ-[年度]-[連番]
  例: PRJ-2024-001

文書識別:
  [プロジェクト]-[文書種別]-[分野]-[連番]-[版]
  例: PRJ2024-001-DWG-ST-0012-v2.0

文書種別コード:
  DWG: 図面
  CAL: 計算書
  SPE: 仕様書
  RPT: 報告書
  MTG: 協議記録
  CHK: チェックリスト

分野コード:
  ST: 構造
  PL: 平面
  CR: 断面
  EL: 電気
  ME: 機械
```

### トレーサビリティマトリクス

```
要求事項 ←→ 設計インプット ←→ 設計計算 ←→ 図面 ←→ 数量 ←→ 施工
    ↓              ↓              ↓         ↓        ↓        ↓
  変更履歴      変更履歴       変更履歴   変更履歴  変更履歴  変更履歴
```

## 8.5.6 変更の管理

### 要求事項

```yaml
適用範囲: 製造又はサービス提供に関する変更
目的: 要求事項への継続的な適合を確実にする
実施: 必要な程度までレビューし管理する

記録必須項目:
  1. レビューの結果
  2. 変更を正式に許可した人
  3. レビューから生じた必要な処置
```

### 変更管理プロセス

```
1. 変更要求（ECR: Engineering Change Request）
   ├── 変更内容の明確化
   ├── 変更理由
   └── 変更要求者

2. 影響評価
   ├── 技術的影響
   ├── 品質への影響
   ├── 工程への影響
   ├── コストへの影響
   └── 安全への影響

3. レビュー
   ├── 評価結果の審議
   ├── 代替案の検討
   └── 承認/却下判定

4. 変更通知（ECN: Engineering Change Notice）
   ├── 承認された変更内容
   ├── 実施方法
   ├── 実施時期
   └── 関係者への周知

5. 変更実施
   ├── 文書・図面の改訂
   ├── 影響範囲への展開
   └── 旧版の管理

6. 変更検証
   ├── 変更が正しく実施されたか
   ├── 意図しない影響がないか
   └── 記録の完備
```

### 変更の分類

| 区分 | 基準 | 例 | 承認レベル |
|------|------|------|------------|
| Class A | 安全・法令に関わる | 構造寸法変更、材料変更 | 技術審査会 |
| Class B | 性能・機能に影響 | 配筋変更、勾配変更 | 管理技術者 |
| Class C | 軽微な変更 | 誤記訂正、表記統一 | 担当技術者 |

## 品質マネジメント7原則と土木設計

| 原則 | 説明 | 土木設計への適用 |
|------|------|------------------|
| 1. 顧客重視 | 顧客要求の理解と満足 | 発注者要求の明確化、住民ニーズ把握 |
| 2. リーダーシップ | 目的・方向性の一致 | 管理技術者による品質方針の明示 |
| 3. 人々の積極的参加 | 全員の力量発揮 | 技術者の継続教育、チーム協働 |
| 4. プロセスアプローチ | プロセスとしての管理 | 設計工程の可視化、PDCA管理 |
| 5. 改善 | 継続的改善 | 設計プロセスの見直し、教訓活用 |
| 6. 客観的事実に基づく意思決定 | データ分析による決定 | 設計計算・検証データによる判断 |
| 7. 関係性管理 | 利害関係者との関係 | 発注者、施工者、住民との連携 |
