# 日本の土木業界特有の品質管理慣行

## 法的枠組み

### 品確法（公共工事の品質確保の促進に関する法律）

```yaml
制定: 平成17年（2005年）
最新改正: 令和6年（2024年）「第三次・担い手3法」

基本理念:
  - 現在及び将来の公共工事の品質確保
  - 公共工事の担い手の中長期的な育成・確保
  - 災害対応のための体制整備

調査・設計への適用:
  - 公共工事と同様の品質確保を義務付け
  - ICT活用によるデータ連携を推進
  - 働き方改革への対応
```

### 建設業法関連

```yaml
設計図書保管:
  期間: 15年
  根拠: 建築士法施行規則第21条

完成図保管:
  期間: 10年
  根拠: 建設業法第26条の3

打合せ記録保管:
  期間: 10年
  根拠: 建設業法施行規則第26条

帳簿・契約書保管:
  期間: 5年（新築住宅は10年）
  根拠: 建設業法第40条の3
```

## 照査技術者制度

### 制度概要

```yaml
根拠: 土木設計業務等共通仕様書（国土交通省）

目的:
  - 設計成果の品質確保
  - 設計ミス・手戻りの防止
  - 発注者への品質保証

位置づけ:
  - 管理技術者とは別に配置
  - 設計者から独立した立場で照査
```

### 資格要件

以下のいずれかを満たすこと：

| 資格 | 詳細 |
|------|------|
| 技術士 | 総合技術監理部門、または該当する技術部門 |
| 国土交通省登録技術者資格 | 登録規程に基づく資格 |
| RCCM | 該当する登録技術部門 |
| 土木学会認定土木技術者 | 特別上級、上級、または1級 |

### 照査技術者の責務

```yaml
1. 照査計画の作成:
   - 照査項目の設定
   - 照査時期の設定
   - 照査方法の明確化
   - 業務計画書への記載

2. 節目毎の成果確認:
   - 基本設計段階での照査
   - 詳細設計段階での照査
   - 最終成果物の照査

3. 照査報告:
   - 赤黄チェックの実施
   - チェック根拠の明示
   - 照査結果の文書化

4. 照査報告書の提出:
   - 照査結果の総括
   - 指摘事項と対応状況
   - 残存リスクの明示
```

### 赤黄チェック

```yaml
赤チェック:
  定義: 照査担当者によるチェック
  実施者: 照査技術者または照査担当者
  対象: 全ての成果品
  記録: 赤ペンによるマーキング（電子化可）

黄チェック:
  定義: 設計担当者による自己チェック
  実施者: 設計担当者
  対象: 作成した全ての成果品
  記録: 黄ペンによるマーキング（電子化可）

チェック項目例:
  - 設計条件の反映確認
  - 計算過程の検証
  - 図面の寸法・整合性確認
  - 基準類への適合確認
  - 数量計算の検証
```

## RCCM（シビルコンサルティングマネージャ）

### 制度概要

```yaml
認定機関: 一般社団法人 建設コンサルタンツ協会
技術部門: 22種類

技術部門一覧:
  - 河川、砂防及び海岸・海洋
  - 港湾及び空港
  - 電力土木
  - 道路
  - 鉄道
  - 上水道及び工業用水道
  - 下水道
  - 農業土木
  - 森林土木
  - 水産土木
  - 廃棄物
  - 造園
  - 都市計画及び地方計画
  - 地質
  - 土質及び基礎
  - 鋼構造及びコンクリート
  - トンネル
  - 施工計画、施工設備及び積算
  - 建設環境
  - 機械
  - 電気電子
  - 総合技術監理（部門横断）
```

### 役割

| 役割 | 業務内容 |
|------|----------|
| 管理技術者 | 業務の適正な執行を管理 |
| 照査技術者 | 業務成果の照査 |
| 業務担当者 | 技術上の事項を処理 |

### 更新要件

```yaml
更新周期: 4年毎
CPD要件: 100単位以上
  - 講習会参加
  - 論文発表
  - 技術指導
  - 自己学習 等
```

## 電子納品

### 電子納品要領（国土交通省）

```yaml
最新版: 令和5年3月（2025年2月からオンライン電子納品本格運用）

目的:
  - 成果品の電子化による効率化
  - データの長期保存・利活用
  - 維持管理段階への情報継承
```

### フォルダ構成

```
DISK/
├── INDEX_D.XML（業務管理ファイル）
├── INDE_D05.DTD（DTD）
├── REPORT/（報告書）
│   ├── REPORT.XML
│   ├── REP01/（報告書ファイル）
│   └── ORG01/（報告書オリジナル）
├── DRAWING/（図面）
│   ├── DRAWING.XML
│   └── DWG01/（図面ファイル）
├── PHOTO/（写真）
│   ├── PHOTO.XML
│   └── PIC/（写真ファイル）
├── SURVEY/（測量成果）
│   └── SURVEY.XML
├── BORING/（地質データ）
│   └── BORING.XML
└── OTHRS/（その他）
    └── OTHRS.XML
```

### ファイル命名規則

```yaml
基本規則:
  - 半角英数大文字のみ
  - ファイル名: 8文字以内
  - 拡張子: 3文字以内
  - 特殊文字使用不可

図面ファイル名:
  [図面種類][整理番号][改訂履歴].[拡張子]
  例: D0PL0010.P21（平面図、第1枚目、初版）

報告書ファイル名:
  [連番].[拡張子]
  例: REP01001.PDF
```

### 図面ファイル形式

```yaml
CADデータ:
  推奨: SXF (P21/SFC)
  代替: DWG, DXF

ラスタデータ:
  推奨: TIFF (G4圧縮)
  代替: JPEG, PNG

PDFデータ:
  報告書: PDF/A推奨
  図面: ベクタPDF推奨
```

### 電子納品チェックシステム

```yaml
チェック項目:
  - XMLファイルの整合性
  - フォルダ構成の適合性
  - ファイル命名規則の適合性
  - ウイルスチェック
  - ファイル形式の確認

運用:
  - 納品前に必ず実行
  - エラーは全て解消必須
  - 警告は原則解消
```

## BIM/CIM原則適用

### 適用経緯

```yaml
2012年: CIM導入開始（国土交通省）
2018年: BIM/CIMに名称統合
2023年度: 原則適用開始（当初2025年度目標を2年前倒し）
対象: 小規模工事を除く全公共事業
```

### LOD（Level of Detail）定義

| LOD | 段階 | 内容 | 品質管理への適用 |
|-----|------|------|------------------|
| 100 | 概略 | 位置・概形表現 | 初期合意形成 |
| 200 | 概略形状 | 構造形式の識別可能 | 概略数量算出 |
| 300 | 外形表現 | 主要部材の表現 | 干渉チェック基礎 |
| 400 | 詳細表現 | 製作・施工可能な詳細 | 施工計画・積算、配筋確認 |
| 500 | 完成形状 | 竣工時の形状 | 維持管理段階活用 |

### 品質確保の仕組み

```yaml
段階モデル確認書:
  目的: 各フェーズでのモデル品質を受発注者間で確認
  タイミング: 設計段階の節目毎
  内容:
    - モデルのLOD確認
    - 属性情報の確認
    - 整合性の確認

3次元モデル照査時チェックシート:
  目的: モデルの整合性・精度を検証
  項目:
    - 座標系の整合
    - スケールの整合
    - 部材の干渉確認
    - 属性情報の完備

BIM/CIM実施計画書・報告書:
  計画書:
    - 活用目的
    - 作成するモデルの範囲・LOD
    - 作成スケジュール
    - 役割分担
  報告書:
    - 実施結果
    - 活用効果
    - 課題・改善点
```

## 総合評価落札方式

### 評価項目

```yaml
企業の技術力:
  - 同種・類似業務の実績
  - 過去の業務成績
  - 表彰実績
  - ISO認証取得状況

予定技術者の能力:
  - 資格（技術士、RCCM等）
  - 業務成績
  - 同種・類似業務経験
  - 手持ち業務量

技術提案:
  - 実施方針
  - 評価テーマへの対応
  - 技術的所見
```

### 配点傾向

```yaml
傾向1: 予定技術者重視
  - 企業より技術者の評価を重視
  - 技術者の経験・実績が重要

傾向2: 成績・表彰重視
  - 資格・実績より成績の配点が高い
  - 表彰実績が加点要素

傾向3: 技術提案の差別化
  - 独自の技術的知見
  - 具体的な課題解決策
```

## NETIS（新技術情報提供システム）

### 概要

```yaml
運営: 国土交通省
目的: 新技術の活用促進
登録技術数: 約3,000件

令和5年度から:
  - 直轄工事でNETIS登録技術の活用が原則義務化
  - 活用効果調査の結果に基づく評価
```

### 評価区分

| 区分 | 説明 | 活用メリット |
|------|------|--------------|
| VE評価 | 活用効果評価が高い | 総合評価で加点大 |
| 推奨技術 | 推奨される技術 | 総合評価で加点 |
| 設計比較対象技術 | 設計段階で比較検討 | 採用実績となる |
| 活用促進技術 | 活用を促進する技術 | 採用実績となる |
| 準推奨技術 | 特定条件で推奨 | 条件付き加点 |

### 活用時のメリット

```yaml
総合評価落札方式:
  - 技術提案での加点
  - 企業の技術力評価で加点

工事成績評定:
  - 最大3点の加点
  - 創意工夫・社会性等で評価
```

## i-Construction

### 概要

```yaml
提唱: 2015年（国土交通省）
目標: 2025年までに建設現場の生産性2割向上

3本柱:
  1. ICTの全面的な活用（ICT土工等）
  2. コンクリート工の規格標準化
  3. 施工時期の平準化
```

### ICT土工と品質管理

```yaml
3次元測量:
  - ドローン測量
  - レーザースキャナー
  - 測量工数の大幅削減

3次元設計データ:
  - 3次元起工測量との照合
  - 施工での活用
  - 出来形管理への連携

ICT建機:
  - マシンコントロール
  - マシンガイダンス
  - リアルタイム施工管理

3次元出来形管理:
  - 面的な品質確認
  - リアルタイム出来形把握
  - 書類作成の効率化
```

### 品質管理への効果

| 項目 | 従来 | ICT活用 |
|------|------|---------|
| 測量 | 横断測量（点管理） | 面的測量（面管理） |
| 出来形確認 | 抜き取り検査 | 全面検査可能 |
| データ蓄積 | 紙ベース | デジタルデータ |
| 品質確認タイミング | 事後確認 | リアルタイム |
